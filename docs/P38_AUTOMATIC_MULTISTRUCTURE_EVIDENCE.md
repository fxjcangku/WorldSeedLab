# WorldSeedLab · P3.8 多结构自动材料取证 + 中文研究控制台

> 研发阶段：当前 PR #32 真实双版本验收进行中。**目标始终是自定义地形生成规律与完整64位Seed可辨识性**，建筑只是条件证据链之一。不得宣传“破解全部服务器”。

## 普通玩家使用

Minecraft 26.1.2 / 26.2 + Java25 + Fabric原生客户端。进入目标世界后，按 **F8** 在明显的一键自动取证按钮启动，或者在游戏原生聊天执行 `/wsl auto on` 一次。随后正常探索，不需要每座遗迹执行标记、双角或导出；自动记录本地已加载FULL区块的真实方块指纹、原版/自定义群系、地表高度以及已配置的STRATA细节。默认不开始、不请求额外Chunk、不访问管理员命令/Seed/NBT、不联网传输原始坐标。

### 自动扫描状态与落盘

- 原P2.6稀疏指纹扫描保持每Tick最多64个额外BlockState和一个区块游标；在近水面与海床具有明显高差的已加载FULL区块中，水平采样从4×4列提高到8×8列（仍固定逐Tick预算），并分别从真实`WORLD_SURFACE`与`OCEAN_FLOOR`派生垂直偏移。
- 每个客户端已完成区块会自动保存材质候选至HMAC世界/维度隔离目录的 `structure-candidates-v2.jsonl`；完成索引用 `structure-scanned-v2.csv`，此前v1档案全部保留且不会阻止v2重新取证。
- 无材料候选的已完成区块只记录完成索引，**不能证明结构不存在**。坐标仅保存在用户本机原始证据中；命令/UI只公开聚合计数和中文候选类型。所有材料候选的`natural_origin_verified=false`、`structure_start_known=false`。
- P3.6 自动沙漠神殿的完整证据仍单独保存到 `p36-automatic-footprint/client-auto-desert-*.properties`，独立不受P3.8指纹变更干扰。
- `/wsl help`显示中文命令分区，`/wsl auto status`分别显示真正写盘、材料类型、候选组与卸载异常，`/wsl structures`按类别显示自动候选；F8大按钮可开启或停止，地图返回保持同一控制器。

## 真实验收与负例原则

- Java25/Gradle9.6.1双版`clean build`包含原版P2.6结构材料正反例（海晶石、船体、暖/冷遗迹、普通海床不应误判、假的矿物无效）以及P3.6/P2.9/Z3回归。
- P3.6原来的真Fabric GUI双版E2E必须依旧能一次授权自动保存四座真实受控沙漠神殿，并在普通客户端取证之后独立后验FULL/StructureStart、2FIT+1HOLDOUT与错误Salt/Seed。
- P3.8另有**受控人工材料场景**：测试服务器用RCON摆放海洋神殿/暖水遗迹/冷水遗迹/沉船的真实Minecraft方块及水体，客户端只执行过一次自动授权，不逐座使用客户端标记命令；读取客户端自身自动生成的v2 JSONL，证明四种材料类别可被识别。该测试的天然来源**确定为人工夹具**，所以绝不作为StructureStart真值、Seed求解约束或未知目标服成功率统计。
- 如 P3.8人工夹具未通过，不能把合成分类器单测冒充双版本自动识别成功。真正自定义地形/人工混合历史、原版与插件建筑相似度的召回率和误报率需要后续新受控集及用户的非公开实测数据。

## 后续研发主线

P3.7/P3.8下一重点是自定义地形生成器前向模型（非原版群系、噪声/地层/海床特征）、历史混合区块识别与未知Salt多模型审计。只有独立校准、真实完整结构起点的证明和FIT/HOLDOUT存在时才能进行低48位条件筛选；完整64位还需要高16位独立验证。**结构识别的数量不等于完整Seed的信息量。**
