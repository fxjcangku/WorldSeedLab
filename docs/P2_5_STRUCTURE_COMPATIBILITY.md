# WorldSeedLab · P2.5 原版结构生成兼容性研究方案

> 研究设计版 · 2026-10-14 · **尚未实现结构 Seed 求解器，也没有真实服务器种子**
>
> 目标：在 Minecraft Java 26.1.2 / 26.2 中，判断混合自定义地形服务器的部分原版建筑是否仍遵循原版结构放置规则。普通 Fabric 客户端、无后台权限、原创算法。

## 核心问题：结构“看起来是原版”≠“位置服从原版随机放置”

同一服务器可以保留沉船、村庄、神殿的外观，同时用插件自行安放建筑。P2.5 的第一项任务不是破解，而是识别**哪种结构证据有资格约束随机种子**。

定义四个阶段：

1. **OBSERVED**：玩家看到建筑并记录位置。此位置只是玩家当前位置。
2. **CANDIDATE_STRUCTURE**：客户端仅根据方块特征推断建筑类型，可能是人工建造或自定义结构。
3. **PLACEMENT_REGION**：根据识别到的建筑外形和朝向，得到一个包含可能结构起始区块的区域（不能伪装为精确起点）。
4. **VERIFIED_START**：只能在可审计的已知 Seed / 可验证原版测试世界中确定真实生成起始区块；真实多人服中的候选起点仍需独立证据或概率/集合约束。

**默认规则：手动标记不能直接送入原版种子约束求解器。**

## P2.5 模型结构

```text
已加载区块及建筑现场
    ├─ P1 三维群系
    ├─ P2 高度图 / 地表材质 / 地下分层

                  │
                  ▼
           Evidence Classifier

                  │

           Placement Hypotheses
     random_spread / concentric_rings / 自定义未知
                  │
                  ▼
         Local Known-Seed Sandbox
   独立复现该 Minecraft 版本的结构起点生成
                  │
                  ▼
           Compatibility Verdict
UNKNOWN / INSUFFICIENT_EVIDENCE /
MODEL_COMPATIBLE / MODEL_INCOMPATIBLE
                  │
                  ▼
     候选结构种子研究（另一个阶段）
```

## 优先结构与取证准确性

| 对象 | 第一阶段方法 | 风险 |
|---|---|---|
| 沉船、沙漠/丛林神殿、雪屋、女巫小屋 | 人工标记 + 可选方块形态识别 | 玩家站位不是建筑起点，沉船形态和方向不固定 |
| 海底神殿、掠夺者前哨 | 建筑轮廓与空间范围估计 | 地形、朝向、被破坏及区块边界影响定位 |
| 村庄 | 标注「未分类村庄」而非硬套 plains | 变种、道路与地形适配，建筑中心不是生成起点 |
| 要塞、远古城市、矿井、试炼密室 | 先积累证据，不直接混用随机散布模型 | 生成规则和群系约束不同 |
| 下界堡垒、猪灵堡垒、末地城 | 独立维度与规则模型，不能和主世界结构混合 | 数据可用性与放置算法不同 |
| 人工建筑及服务器插件建筑 | 只保留观察记录并标记来源未知 | 强行纳入会污染结果 |

> 上表属于研究对象规划；哪些结构适用于 Java 26.2 的哪种放置规则，需要从目标版本实际 Mojmap 及已知 Seed 世界验证后再确认。**不能套旧版本常数、盐值和 RNG 例程。**

## 原创算法验证的次序

1. 在 26.1.2 和 26.2 分别创建已知世界 Seed 的单人测试环境，读取对应版本真实游戏生成代码。
2. 独立实现结构候选位置计算：世界种子输入、放置方法、region 网格、相对偏移、salt 和限制条件等。
3. 用已知真值对照：真实结构起始区块 vs 自研实现输出；跨地域与负坐标回归。
4. 设计自定义数据包或控制样本：保留原版放置算法、但修改地形/群系的正例；修改放置参数、伪造人工建筑和混合历史区块的反例。
5. 将真实服务器候选结构的**可能起始区域**与位置模型做兼容性比较。若存在多种解释，保留集合，不得硬选一个坐标。
6. 从计算中留出部分结构和区域，独立验证；与求解使用的证据绝不重叠。

## 为什么不能马上计算完整世界种子

- 原版常见结构放置逻辑可能主要约束种子的低位信息，但实际 26.x 具体规则必须先核实，不能将“低 48 位”直接冒充完整 64 位世界 Seed。
- 群系、地形高度、方块状态可能由自定义世界生成器决定；不知道算法与参数，无法直接用它们筛掉种子候选。
- 世界历史不清楚，区块可能跨版本或跨生成器；使用 `/wsl epoch new` 手动隔离已知的整图重置（不自动推断），仍需区域时代判别来处理同一存档的旧区块。
- 结构可能因群系检查、地形、被玩家破坏或人工安放而消失/出现；未观察到结构不能直接作为强负证据。
- P2.5 **只判定模型适用性**，Seed 求解属于后续明确验收的 P3。

## 用户正常跑图要做什么

- 先只在获准使用这类模组的服务器进行正常探索，使用 F8 主动开启观测。
- 跑图优先覆盖**不同地貌、不同 region、相隔较远的自然结构**，避免绕同一个村庄重复取证。
- 推荐分开试验低成本群系/高度图、多高度图、纵向剖面档位；不可在报告中将未扫描的区域当成已观测。
- 发现结构时可用 `/wsl marks` 查看可人工标记类型，再 `/wsl mark <类型>` 记录，游戏不会替你验证结构是否自然生成。
- 用 `/wsl report` 导出中文研究摘要。**优先发 research-report.txt**；原始 JSONL 含精确地图坐标，只有确认可以共享时再进行脱敏传输。不要上传 `identity.key`。
- 只有真实多人服日志不够时，再提交自建的已知 Seed 测试世界用于算法复核。

## P2.5 通过/失败标准

- **正例：** 相同版本、已知 Seed 的不同世界和正负坐标上，结构位置独立实现与真值一致。
- **反例：** 错误模型、不同 salt、假建筑、错世界/错维度证据被拒绝或明确降级为“不确定”。
- **精度：** 明确区分玩家观察点、估计边界框、可能起始区块集合、可证明起始区块。
- **覆盖率：** 记录实际完成的区块与高度网格，不能仅凭加载区块数量推断全图已被扫描。
- **结果：** 证据不足输出 `INSUFFICIENT_EVIDENCE`；没有可靠原版模型则输出 `UNKNOWN`。只有跨独立样本验证后才能称 `MODEL_COMPATIBLE`，且仅对指定规则和样本范围成立。
- **性能：** 求解器以后只在独立离线工作线程运行，不能阻塞 Minecraft 客户端 tick 或 GUI。

### 技术验收关卡

P2.5 的第一份可执行代码应该是**已知 Seed 世界的纯离线随机结构放置回归套件**，不是在真实多人服务器上直接暴力搜索 64 位种子。
