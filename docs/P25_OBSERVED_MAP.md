# WorldSeedLab · P2.5 已探索真实地图

> 阶段：地图 MVP（预览） · Minecraft Java 26.1.2 / 26.2 · Fabric / Java 25 / Mojmap

## 核心原则

这不是从 Seed 生成的预测地图，也不使用 Chunkbase 或其它网站来补全未知位置。

**一切有颜色的格点来自客户端实际收过并已保存的证据。** 没采集过的区块、没有精确对应高度的群系格点始终显示为「未知」，不能理解成没有群系或没有地形。

### 四个图层

| 图层 | 取证来源 | 绘图原则 |
|---|---|---|
| **地表地图（默认）** | 已加载 FULL 区块的逐方块 BlockState、真实表面高度及原生 MapColor | 每区块 16×16 个独立方块列；不会把旧 4×4 群系格插值成细节 |
| **地表群系** | 既有地表高度图 + 对应位置附近的三维群系格点 | 只有两类实际证据同时存在才显示颜色 |
| **指定高度群系** | 原有 P1 三维 quart 群系采样 | 选择 Y 高度，查询该 Y 附近的真实格点；信息栏显示实际观测 Y |
| **地形高度** | 原有 P2 WORLD_SURFACE 16 列高度样本 | 按高度上色；无记录不填色 |

地形高度和群系采样精度并不相同。以默认垂直间距 8 方块为例，显示的「Y=70」格点可能来自实际观测 Y=66；地图信息栏会显示真实 Y，不会隐藏误差或在未观测深度伪造新样本。

自定义群系（例如 `deeper_dark:*`）使用固定哈希配色，以方便辨认；颜色不代表服务器纹理或真实草地颜色。

地表地图使用真实方块的原生地图材质色，能保留相邻道路、建筑、水面等不同方块列的颜色边界；它不是资源包纹理或卫星截图。原生地图色透明的方块会在同列内继续向下读取，直到实际有色方块或世界底部；每次读取同样受到 Tick 预算限制。完整列中没有可见地图色时保留空白，不用群系颜色补洞。

## 操作

1. 安装两个版本中与游戏版本匹配的 CI 测试构建产物。
2. 在允许使用取证工具的服务器中，按 **F8** 打开地图主页，或者输入 **`/wsl map`**。
3. 默认查看逐方块「地表地图」，也可切换地表群系、指定高度群系或地形高度。
4. 选择「指定高度群系」后，右侧「Y - / Y +」以 16 方块调整目标高度；下方加减或滚轮调整地图尺度。
5. 拖动地图平移；「回到玩家」将观察中心移至当前玩家位置。地表图默认每实际方块2个逻辑像素，放大最高为8个逻辑像素，整张面板随窗口缩放。
6. 鼠标悬停地图格点可查看世界 X/Z、实际 Y、群系 ID 或高度值。
7. 地图由有界后台工作线程读取；需要重新读取本机已保存证据时使用「刷新」。同一视窗刷新期间保留上一份真实快照，不会先整幅闪空。

**默认不需要再次开启采集即可查看已经写盘的地图。** 但第一次必须曾经主动开启过采集，且当前玩家处于可识别的世界；地图按本机世界纪元/维度隔离。

**升级前只有群系/高度证据的区域没有逐方块地表色。** 用户再次主动开启「基础采集」或「联合取证」后，只对当前已加载 FULL 区块补采地表；旧群系完成记录不会阻止这个新图层。不会因打开地图自动采集，也不会删除旧记录来强迫重扫。

## 数据保存与安全

原群系采样成功写入 `evidence.jsonl` 时同步建立 `observed-map` 群系索引。逐方块地表在同一地图归档中增加 surface 瓦片类型，直接保存完整256列的高度、ARGB、采样时间和世界/维度/版本身份；没有另建重复地图索引体系。surface 按游戏版本隔离，两个目标版本可以并存，原始证据与旧图层保持不变。

```text
.minecraft/config/worldseedlab/observations/
└── worlds/<本机 HMAC 世界指纹>/dimensions/<本机维度散列>/
    ├── evidence.jsonl                原始 P1 群系及手动结构取证
    ├── terrain.jsonl                 原始 P2 高度观测
    ├── completed-chunks.csv          原有完成索引
    └── observed-map/
        ├── biomes/r.<区块区域>/b.<区块X>.<区块Z>.<垂直间距>.wsl.gz
        ├── heights/r.<区块区域>/h.<区块X>.<区块Z>.wsl.gz
        ├── surface/<游戏版本>/r.<区块区域>/s.<区块X>.<区块Z>.wsl.gz
        ├── surface/<游戏版本>/completed-chunks.csv
        └── markers/r.<区块区域>/m.<随机ID>.wsl.gz
```

- 地图缓存中包含真实坐标和曾采样的群系，**不要把它连同私人服务器数据直接公开**。
- 地图不读取服务器后台，不会取得完整 Seed，也不会为了显示地图而向服务器请求未加载区块。
- 当前地图显示的是已保存快照；采样时玩家或服务器之后修改的地形，不能视为最初自然生成状态。
- 手动标记的建筑仅代表玩家观察点，不是结构真正的生成起始区块。
- 旧版本 **只有 `evidence.jsonl`、没有 `observed-map` 群系索引**时，历史群系不会自动出现在群系图层。**旧群系已完成的区块，不会因为玩家再次飞过就自动重扫群系**；这部分仍需未来的受控离线索引迁移工具。新地表图层可在用户主动开启采集后独立补采，无需删除旧证据或完成日志。
- 一个地图瓦片损坏时，那个瓦片保持未知，其余通过校验的真实瓦片继续显示；快照会明确标记「部分地图索引读取失败」。这不代表完整覆盖，不能用预测值填补坏瓦片。原始证据与完成索引都不因此删除或改写。
- 不论当前有没有 SeedcrackerX 输出，世界地图都不会拿候选 Seed 或其它生成规则填充空白。

## 性能约束

- 查询范围最多 128×96 个 quart，即地表层最多 512×384 个实际方块列；GUI 使用更小的有界视窗。群系层仍按原始 quart 分辨率显示。
- 后台地图读取采用单线程、有界队列；平移和切层后，旧查询结果不会盖过新视图。
- 关闭页面立即撤销查询世代；关闭后的请求返回明确终态，不会停在永久「读取中」。切世界/切图层/平移时撤下旧快照，刷新同一作用域与视窗才允许暂留已有快照。
- 每次仅查询当前可见区块的地图小瓦片，不扫描整个世界 `evidence.jsonl`。
- 采集继续使用 P1/P2 现有的 Tick 预算、单线程磁盘队列和世界/维度安全保护。
- 用户启用基础或联合取证后，地表采样每 Tick 最多额外读取32次 BlockState和32次高度图，透明方块向下查找也计算在预算中。只接受已有 WORLD_SURFACE 高度图的 FULL 区块，避免查询缺失高度图时隐式整块扫描。完整256列才提交既有有界异步写盘队列；先原子写入瓦片，再记同版本完成状态。中途区块卸载丢弃未完成游标，停止/切世界不提交部分数据，磁盘异常沿用现有失败关闭逻辑。
- 后台快照把同一行中严格相邻、颜色相同的实际方块列合并为绘制段，减少渲染指令；不跨未知缺口、不跨不同颜色，悬停仍查询独立的真实方块列。逐格交错颜色的最坏情况仍受原视窗大小限制。
- 如果扫描速度高于区块保持加载的速度，地图会有缺口；结合 `/wsl report` 的覆盖统计分析即可。
- 4K 显示器、高 GUI 缩放与 Vulkan/OpenGL 的实际效果仍需 `runClient` 验收，编译成功不等于画面正常。

## 空白地图的含义与读取回归

地图分别说明「当前视窗没有已保存证据」「有群系但缺地表高度」「有高度但缺对应群系」「选定高度附近未观测」「旧证据缺地图索引」与「部分索引读取失败」。前四种状态可以通过已有图层、已采集位置或手动采集后的刷新核对；旧证据缺索引不等于重复跑图能修复。

26.1.2 与 26.2 的真实 `ChunkAccess.getHeight(WORLD_SURFACE, x, z)` 都已经返回最高表面方块 Y（内部为 `Heightmap.getFirstAvailable - 1`）。地图直接使用保存值选择最近的已观测 quart 群系，不再额外减一；实际采样 Y 仍独立展示。

`p25MapSmokeTest` 覆盖缺失图层、边界 Y、坏瓦片隔离与历史证据保留，并通过可控线程时序检查快速连续请求、同视窗刷新、作用域切换、读取异常重试和关闭后请求。这些是纯 Java/本地索引回归；真实游戏画面及两个版本的交互验收仍须分别进行。

其中逐方块回归额外验证256个独立方块列、透明色读取预算、部分/卸载游标拒绝、旧群系进度不阻止补采、跨HMAC/维度/版本隔离、错目录瓦片拒绝、异步写盘计数及I/O失败。合成棋盘色只用于测试数据通路，不能作为真实游戏地表截图或采集验收。

## P2.5 与后续 Seed 研究的关系

真实地图可以定位值得重复验证的群系边界、结构观察候选及地形特征，但**地图不是 Seed 求解器**。P2.5 结构规则兼容性研究仍需已知 Seed 的单人世界真值、精确或有边界的结构起点，以及未参与训练的独立验证样本。

真实地图与原创结构种子研究可以互相辅助，但必须将「我看到了什么」「我假设了什么」「我验证了什么」明确分开。
