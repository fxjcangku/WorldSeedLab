# WorldSeedLab · P2.8 / P3 位向量求解研究与真假矿判断边界

> 目标版本：Minecraft Java 26.1.2 / 26.2，Java 25，Fabric/Mojmap
> 状态：原创建模与离线求解试验。**不是已验证的自定义服务器 Seed 破解器，也不是原版矿点导航器。**

## 为什么需要这个阶段

P2.7 的 Java LCG + RandomSpread 模型已与两版 Minecraft 本体对照通过，但有限窗口逐个尝试低 48 位候选，不足以实用地遍历完整 2^48 空间。P2.8 将**同一套已验证的正向数学公式**转换成 QF_BV 位向量约束，让通用离线 SMT 引擎尝试直接求得满足多个结构起点的候选，而不是手工移植任何现有 SeedCrackerX 破解算法。

完整链路：用户显式给出的结构集合参数和**已确认或有界的真实结构起始区块** → 48 位位向量 SMT → 本地 Z3 → 低48候选 → Java 逐位精确复核 FIT → 独立 HOLDOUT 验证 → 条件化结论。

## 已实现的数学层

- `SymbolicRandomSpread`：48bit LCG；与 Java `nextInt` 一致的 31bit 输出、二的幂乘法分支、非二次幂余数及拒绝采样条件。支持 RandomSpread 的 LINEAR / TRIANGULAR、负区块 Region 和不同 Salt。
- `LocalSmtSeedSolver`：显式执行本机 Z3；所有模型都由 P2.7 精确 Java RNG 逐项复算，训练和留出完全分离；持有时间上限、模型个数上限及临时文件清理。
- `SymbolicSeedCli`：在游戏之外运行，不操作玩家、鼠标、客户端 Tick 或网络接口。
- 自动化：两版 CI 除了原有随机放置 162 组本体对照以外，增加 SMT 格式正反例和 **实际 Z3 求解**的集成回归。

### 重要数学限制：拒绝抽样路径

Java `nextInt(bound)` 对非 2 的幂会进行拒绝抽样，极少数情况下连续重新读取随机数。此版 SMT 默认只展开每次调用的**最多 3 次**读取，要求其中一次被接受。真实 Java 复核始终使用完整循环。由于理论上可能超过 3 次，SMT 的 `unsat` **不能证明全部可能 Seed 都已被排除**。结果将明确标记 `incompleteRejectionPaths`。

当 `spacing - separation` 是 2 的幂时，Java 每次只抽一次，因此没有上述拒绝重采截断。但结构真实生成仍可能经过 biome/frequency/exclusion 过滤。

### 为什么不能直接从跑图材料推算结构 Seed

P2.6 的沙岩、海晶石或木质材料线索，和 `/wsl mark` 的玩家站位，都**不等于真正的结构生成起始区块**。P2.8 的输入类型仍只接受 `REFERENCE_FROM_CONTROL_WORLD` 或几何学推断的 `GEOMETRY_ESTIMATE` 范围，必须明确其不确定性，并且至少提供 **2 条 FIT + 1 条独立 HOLDOUT**。同一结构集合中重叠的 Region 不能重复计数。

完整 48 位结构低位信息 ≠ 完整 64 位后台世界 Seed。只有知道该服务器的实际结构集合 spacing/separation/Salt/随机算法时，位向量匹配才具有相应的解释意义。未知 Salt 与 Seed 存在加法混淆，不能单靠同一种结构集合唯一恢复后台 Seed。

## 本机研究使用方法

1. 安装 JDK 25、Gradle 9.6.1 和来自可信发行渠道的 **Z3 命令行工具**，确保终端可执行 `z3 --version`。CI 的 Z3 只供测试，不会打包到 Fabric JAR。
2. 参照 [P2.7 输入规范](P27_RANDOM_SPREAD_SOLVER.md) 创建明确来源的 `solver-input.properties`，包含结构模型、作用域、起点候选范围和 FIT/HOLDOUT 分组。设置 `search.startLow48`、`search.endExclusive`；需要完整 48 位变量空间时，半开区间可设置 `0` 到 `281474976710656`，但不能保证短时间求得解。
3. 显式运行离线命令：

```bash
gradle -PmcVersion=26.2 -PsolverInput=/path/to/solver-input.properties -PsmtMaxModels=12 p28SmtResearch
```

4. 结果为 `LOW48_CANDIDATE`，并附精确 Java FIT/HOLDOUT 通过数量、后端状态、求解时长预算、拒绝复核的次数与保留的推断限制。没有候选可能只是超时、拒绝采样路径未全部展开、输入模型错误或结构起点不可信。
5. **不要把日志中任何低48数字直接当作完整 Seed 交给种子矿点网站**；网站还要求正确的世界版本及矿石生成规则。

### 示例数据与真实数据

仓库提供的自动化测试使用一个已知合成 Seed 的受控测试场景，只测试数学求解器逻辑。只有在对应 Minecraft 版本的实际单人世界核对了结构起始区块、结构集合参数、独立留出结构之后，才能把该模型用于真正外部世界。

## 专门针对你的服务器：假矿与种子挖矿

即使最终得出确实有效的后台 64 位世界 Seed，**真实矿点预测仍取决于矿脉生成算法是否原版兼容**。

| 服务器机制 | 真实 Seed 是否足够预测矿点 |
|---|---|
| 只在客户端把石头显示成假矿，服务器真实矿脉仍按原版生成 | 可能；仍需对应版本、矿石放置参数和挖掘后的独立复核 |
| 原版世界 Seed，但自定义地形/群系并修改矿石装饰规则 | Seed 本身不足以推出真实矿点 |
| 结构 Seed 和矿物生成 Seed 不同，或服主修改 Salt/插件生成 | 无法用单一原版种子矿点模型保证命中 |
| 客户端接收到的矿石方块由反透视/防作弊伪装 | 不能以“看到矿石”作为天然矿分布真值 |

**后续单独建立矿物生成兼容性实验**：选定已确认的种子候选，在获准的受控区域对独立真实矿脉样本做验证，区分“客户端显示矿石”和“实际挖掘后的真实掉落”。在做到这一步之前，WorldSeedLab 不应宣称可以可靠导航真矿。

## 验收门槛

- Java 25 双版本 Gradle `clean build`，包含 P2.8 生成器、真实 Z3 集成、P2.7 Minecraft 本体 162 组对照，以及全部 P0～P2.6 回归。
- 有效输入恢复已知低48合成候选；错误候选被排除；非二幂与三角 RNG 模型可由通用 SMT 引擎解出并由 Java 精确复核。
- 跨世界/维度/版本的结构位置混合、重复 Region、无留出证据、虚假人工起点必须拒绝。
- Z3 不可用、执行超时、模型无效必须显示明确失败状态，不可声称“真实服务器没有 Seed”。
- `runClient`、结构真实起点识别、全48空间计算速度，以及真实矿石生成兼容性均须另行实测，不能由 CI 编译成功代替。
