# WorldSeedLab · P2 世界生成环境取证与研究日志

> 阶段：**P2 Diagnostics Preview** · 目标版本：Minecraft Java 26.1.2 / 26.2  
> 目的：在 P1 真实群系采样基础上记录自定义维度、地形高度变化和可分享的中文汇总报告。**此阶段不负责反推 Seed。**

## 一、怎么配合鞘翅跑图？

1. 在独立 Fabric 客户端加载 WorldSeedLab；确认服务器规则允许这一研究工具。
2. 进入服务器，按 **F8** 或输入 `/wsl gui` 打开液态玻璃控制面板。
3. 根据飞行速度与性能选择扫描半径（默认 4 区块）、纵向精度（默认 8 格）与每 Tick 预算（默认 128）。
4. 手动点击**开始采集**，再通过普通飞行或独立鞘翅寻路探索新的地形。不需要让 WorldSeedLab 接管移动或寻路，也不依赖 yiyiaddon。
5. 在已经探索的范围中，P1 读取客户端已加载区块的三维群系，P2 在每 12 Tick 内最多额外采样两个已加载区块的地表高度。
6. 进入其它维度、切服、断线或者手动停止时，观测会结束；当前会话**不会自动跨维度恢复**。进入新维度后需再次主动开始。
7. 停止采集并等几秒钟让待写入队列归零，再执行 **`/wsl report`** 导出本次可分享的中文诊断摘要，使用 **`/wsl path`** 查看日志目录。正常退出客户端也会有限等待日志写入，并尝试自动生成报告；非正常退出无法保证此操作执行。

> 跑得远可能收集到更多的独立观测区块，但“观察范围大”不代表“可以解出 Seed”。高速鞘翅可能在完成采样前令部分区块卸载，因此报告的覆盖率**不能认为达到 100%**。

## 二、采到的维度资料是什么？

每次启动一个采集会话，在本地 `dimension-profile.jsonl` 中记录：

| 字段 | 含义 | 限制 |
| --- | --- | --- |
| dimension | 例如 `minecraft:overworld` 或 `deeper_dark:deep_realm` | 真实注册键，仅证明客户端看见该维度 |
| client_version | 当前 Minecraft 游戏版本 | 不代表服务器地图最初生成版本 |
| min_build_y / max_build_y_exclusive | 当前维度的建造高度范围 | 不代表所有自定义生成器参数 |
| sea_level | 游戏客户端可获得的参考海平面 | 部分自定义维度可能与实际水位不同 |
| skylight / ceiling | 天空光与有顶属性 | 只来自客户端可见的维度类型 |
| ultra_warm | 未确认的属性输出 `null` | 不猜测 Fabric/Mojmap 不存在的 API |
| observed_at | 记录时间 | 仅说明客户端何时看到这些信息 |

此外，本版还会保存 `advertised-dimensions.jsonl`：若 26.1.2 / 26.2 客户端连接对象提供已公布的维度键清单，将记录注册 ID、来源标记 `ADVERTISED` 和观察时间；若连接对象不可用，仅记录当前维度并标记 `CURRENT_ONLY`。**仅公布 ≠ 已到访 ≠ 已加载该维度区块**。导出的中文报告按这个区别展示完整清单。

**不能获取**：服务器私有世界种子、NoiseSettings 完整参数、世界生成器插件私有配置、所有尚未探索的维度或地图历史。

## 三、采到的地形证据是什么？

- 每区块最多记录 **16 个 4×4 网格中心的 WORLD_SURFACE 高度**。
- 记录区块 X/Z、维度、最高与最低地表高度、与当前客户端关联的版本标识。
- 高度图不能完整识别浮空岛下方、多层洞穴、人工修改历史或生成器噪声源；它是**稀疏的可观测几何特征**。
- 地形和群系日志分别记账；过去 P1 扫过的区块仍可在 P2 进行地形补采。
- 每 12 Tick 最多处理两个地形区块，不触发区块加载请求；磁盘队列满时暂停而不丢弃有效提交。

## 四、本地日志（默认完全离线）

```text
.minecraft/config/worldseedlab/
├── identity.key                                  本地随机 HMAC 秘钥，严禁公开
├── probe.properties                              默认扫描参数，采集开关不持久化
└── observations/
    └── worlds/<HMAC 64位十六进制字符串>/
        └── dimensions/<维度本地散列>/
            ├── evidence.jsonl                   P1 三维群系与手动建筑观察证据
            ├── completed-chunks.csv             P1 群系区块完成索引
            ├── dimension-profile.jsonl          P2 当前已访问维度的元数据
            ├── advertised-dimensions.jsonl      P2 客户端连接公布的维度注册键（未必进入）
            ├── terrain.jsonl                    P2 每区块 16 个地表高度图样本
            ├── terrain-completed.csv            P2 地形独立完成索引
            └── research-report.txt              手动执行 /wsl report 导出的中文汇总
```

**你可以发给我什么？**

推荐先发 **`research-report.txt`**（其中包含已获知的维度 ID 清单以及实际访问维度的区分）。我可以依据里面的维度信息、已观察群系与地形特征，确定下一步哪些原版生成模型值得测试。

如果之后确实需要复核具体结构位置或地形条件，可先将 `evidence.jsonl` 与 `terrain.jsonl` **去除敏感坐标或确认服务器允许共享后**再提交。**绝对不要上传 `identity.key`**。

报告不会记录服务器明文地址或玩家完整轨迹；原始 `.jsonl` 中**包含具体坐标**，这是不同级别的数据。

## 五、当前“破解种子”的技术边界

普通客户端无法直接读取真实世界 Seed。研究路线是：

1. **P1：** 采集已经出现的原版和自定义群系、玩家标记的自然结构观察点。
2. **P2：** 补充地形高度、维度信息，判断世界规则假设所需的证据是否可能取得。
3. **后续生成模型：** 针对已验证适用的 Minecraft 版本，自主实现原版结构放置规则并取得真正的结构起始坐标证据。
4. **候选约束与验证：** 利用多个独立结构计算、筛选候选 Seed，严格区分结构种子与 64 位世界 Seed，并用未参与求解的结构独立确认。

**目前不会根据群系/高度数量“算出”或伪造 Seed**。若服务器修改结构盐值、分布算法或使用自定义生成器，普通原版方法可能不适用。

## 六、验收与已知限制

- 两版本 GitHub Actions 构建、P0/P1/P2 smoke test 需要全部成功。
- 进单人已知 Seed 世界观察地形、群系和维度 ID，确认客户端实际看到的数值与日志一致。
- 自定义维度实测至少一个 `namespace:path` 类型维度，并检查切维度后采集立即停止。
- 验证磁盘不可写、日志损坏、客户端断开、高速飞行与GUI缩放时的失败保护。
- **当前没有完成真实服务器运行测试**；仓库里只有观察架构和研究框架，不提供真正 Seed 求解器。

## 七、采样覆盖质量（P2.4）

扩充后的 `research-report.txt` 将在末尾追加【采样质量与覆盖足迹】，仅包括本次会话已被写入队列接受的：
- X/Z 唯一区块数与 32×32 区块宏区域数；不是整个服务器地图的覆盖百分比。
- 32 方块为一组的 Y 高程带观测格点数量，能发现只扫到地表而漏扫洞穴的异常。
- 区块扫描过程中卸载导致的未完成次数；地下剖面中途卸载次数；磁盘写入背压次数。
- 统计计数不含精确区块位置。实际 `evidence.jsonl` 和 `terrain-detail.jsonl` 仍包含精确 XYZ / 区块坐标，公开共享前必须脱敏。

**这些是采集质量指标，不是地图覆盖百分比、自然生成概率或 Seed 置信度。**

## 八、同 IP 地图重置：世界纪元保护

普通客户端**不能自动证明服务器何时重新创建世界**，只有服务器地址的本机 HMAC 指纹不足以判断生成历史。

- `/wsl epoch` 查看此世界当前本地证据纪元（旧数据兼容为 `legacy`）。
- 确认服主**更换整张地图、替换生成器或全服重开季节**后，在已停止采集且写盘队列排空时，主动输入 `/wsl epoch new`。
- 该命令会产生新的本机随机纪元，之后观测写入全新的 HMAC 世界指纹目录；**原有证据文件不会删除或覆盖**。
- 首次未使用过纪元功能的旧存档仍使用原来的 legacy 目录；配置文件保存在 `config/worldseedlab/epochs/<本机HMAC>.txt`。
- 若一个代理地址连接到多个不同子服务器/世界，**应根据你的实际连接情况分别管理纪元**；仅靠本功能仍无法自动识别子服切换。

切换纪元不等于取得真实 Seed，也不会识别旧区块的原生生成版本。
