# P1 · 世界群系观测与结构取证

> 实现阶段：P1 Observation Preview
>
> 兼容目标：Minecraft Java 26.1.2 / 26.2，Fabric，Java 25。仅采集普通客户端正常可见的数据，尚未实现种子求解器。

## 使用

1. 安装与游戏版本完全一致的 WorldSeedLab 构建产物，并确认服务器规则允许此类客户端研究工具。
2. 进入单人世界或多人服务器；按 **F8**，或输入 **`/wsl gui`**。
3. 在中文液态玻璃面板里调整采样范围与预算（采集启动后先停止才能修改）。
4. 点击 **开始采集**。这一步才会创建本地世界指纹和采集记录。
5. 正常在已经加载的地图中探索。程序只扫描收到客户端的区块，不强行加载未收到的区块。
6. 点击 **停止采集**，或离开世界、切换维度，让采集自动停止。已接收的磁盘任务会在后台有序收尾。
7. 输入 **`/wsl path`** 查看本机存储目录；可将脱敏后的证据用于后续独立验证。

命令：`/wsl`、`/wsl gui`、`/wsl status`、`/wsl about`、`/wsl path`。默认不会自动重新启动采集。

## 数据从哪里来？

扫描使用 **客户端当前已经加载的区块数据**。为了避免只统计“注册了但从未出现”的群系，数据层读取每个观测坐标处的 `ClientLevel.getBiome`，保存返回的注册群系 ID。

- 水平按 4×4 方块的群系 quart 网格中心点采样，每区块每高度层 16 个点。
- 垂直采样间距 **4 / 8 / 16 方块**。默认 **8**：故意跳过部分高度层，速度更快，无法据此证明中间层没有其他群系。
- 枚举从当前世界可获取的最低到最高构建高度，能记录洞穴和地下群系，不仅是表层。
- 单 tick 最多 **32–256** 个采样点（默认 128）；附近区块搜索半径 **1–6**（默认 4）。
- 扫描进度会随玩家探索推进；速度较高时，部分短暂加载过的区块可能来不及完整采样，**不能把未记录视为不存在**。

这些记录是**客户端实际观测样本**，不是服务器完整地图数据、生成器源码、世界种子或生成前噪声输入。服务器可能有额外自定义规则，当前工具无法自动判断。

## 液态玻璃 UI

原生 `GuiGraphicsExtractor` 渲染，仅使用半透明渐变、柔和高光、边框与状态文字模拟玻璃材质；不执行实时背景模糊或直接 OpenGL 操作。

UI 第一阶段包括：

- 开始/停止采集及运行状态；
- 真实观测到的群系 ID 及本次样本次数；
- 完整写入的区块数量、待处理队列与磁盘写入数量；
- 半径、纵向采样间距、tick 预算调整；
- 手动标记沉船、沙漠神殿、村庄（需已开启采集）。

**结构标记不等于结构自动识别。** 手动记录的是玩家当前脚下坐标，未验证该建筑是否自然生成，也**没有**反推出其真实结构起始区块；后续求解阶段不得把这类坐标直接当作精确的结构生成点。

## 本地数据位置与隐私

进入世界后，生成如下结构：

```text
.minecraft/config/worldseedlab/
├── identity.key                         # 本机 32 字节随机秘钥（不要公开）
├── probe.properties                     # 只存设置，不持久化采集开关
└── observations/
    └── worlds/<local_hmac_sha256>/
        └── dimensions/<dimension_hash>/
            ├── evidence.jsonl          # 真实观测记录（有绝对 XYZ）
            └── completed-chunks.csv    # 已确认写入的区块+采样间距
```

- 世界标识从本机私钥与连接信息生成 HMAC 摘要；证据文件名不包含服务器 IP。
- **evidence.jsonl 中包含精确坐标和群系 ID，可能泄露私人服务器位置信息**。上传 Issues 或公开共享前请先脱敏。
- 不上传网络，不读取服务器后台，不获取 Seed，不替玩家移动或开启区块加载。
- 世界/维度变化、客户端异常或写入错误会使采集停用，默认不自动恢复。
- 完整区块优先落盘，再更新完成日志。如果程序在这两次写入之间意外退出，后续重试可能造成少量重复证据，但不会把未持久化的区块伪报为完成。
- 地图历史可能不明，当前只能记录**客户端游戏版本**，不能据此证明每个旧区块生成于哪个服务器版本。
- 世界识别暂基于远端地址或单机世界名称；代理多子服、单机同名存档或地图原地重置应当分别处理。对无法识别的世界会拒绝启动，不能当作完美世界指纹。

## 数据正确性与验收

原始证据格式保留 `schema`、`world_fingerprint`、`dimension`、`client_version`、`kind`、`observed_identifier`、`position`、`origin`、`observed_at`、`note`。

第一轮回归需要验证：

1. 在已知 Seed 单人世界，观察到的群系 ID 与游戏内 F3 所示当前位置一致，并核对自定义资源包添加的群系是否实际生成。
2. 在空白或未加载区块中不产生观测证据；区块远离卸载或断线时不会强行加载。
3. 高速鞘翅飞行的 tick 负载与队列背压有效；文件写入不发生在客户端 tick 线程。
4. 关闭或切换维度后，绝不向旧范围继续开始新采样。
5. 重启客户端后仍可读取同一采样间距的已完成区块索引；修改采样间距时允许新增采样但保留旧文件。
6. 不依赖私人 yiyiaddon 源码；双版本 CI 编译与 P1 核心 smoke test 通过。
7. 通过实机 `runClient` 验证玻璃面板视觉效果、中文显示、按键、鼠标交互与关闭流程。

**尚未实现：** 自动结构识别、结构坐标纠错、候选种子求解、独立规则兼容性判断、完整 64 位 Seed 确认、动态生成器还原。

## 版本验收与后续
