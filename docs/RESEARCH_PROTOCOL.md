# WorldSeedLab / 证据与验证协议（草案）

**协议版本：** 0.1（研究设计阶段，尚无客户端实现）

## 1. 三种试验环境

| 环境 | 数据来源 | 任务 | 通过条件 |
| --- | --- | --- | --- |
| A · 原版对照 | 已知 Seed 的 26.1.2、26.2 单人世界 | 基础采集与结构放置模型校验 | 候选结构位置与已知 Seed 推导一致 |
| B · 自定义控制组 | 自建数据包或世界生成配置 | 修改地形/群系与结构参数，设置正反例 | 正例保持兼容，反例可被识别或标记不确定 |
| C · 真实服务器 | 普通 Fabric 客户端可见数据 | 检查自定义地形+原版建筑的生成兼容性 | 不借助后台权限，收集可重复检查的证据 |

首个真实场景：**Minecraft 26.2、自定义地形、保留原版村庄/神殿/沉船、地图历史未知**。

## 2. 数据采集边界

普通客户端可以观察区块、可见方块以及客户端获知的群系等数据；**不应假设客户端会直接接收服务器的完整世界 Seed、原始结构放置起始坐标或全部生成器配置**。

每个证据项至少记录：

| 字段 | 意义 |
| --- | --- |
| `source_id` | 本地匿名世界/服务器指纹，避免跨服混淆 |
| `dimension` | 维度注册键 |
| `game_version` | 观察时客户端版本；如未知应标记 |
| `observed_at` | 观察时间，仅用于区分采样批次 |
| `kind` | `biome_observation` / `structure_observation` 等 |
| `position` | 方块坐标与明确的采样口径 |
| `origin` | 自动判定、用户手动、离线测试等证据来源 |
| `confidence` | 观察置信度，不是 Seed 正确率 |
| `verification_group` | `solve` / `holdout`，用于留出复核 |

默认不公开完整服务器地址、精确玩家活动轨迹或私人服坐标。

## 3. 结构证据的严谨性

- 建筑实体可见坐标 **不等于** 结构生成起始区块坐标。
- 建筑看起来像原版，不等于它由原版生成器创建。
- 不同版本可能导致结构生成规则、适用群系或结构起点差异。
- 地图升级、区块预生成、结构人工迁移都可能产生冲突信息。
- 应在计算前过滤重复观测、歧义结构、不同维度与未确认版本的样本。

对于真实服务器，先记录候选结构和识别证据；结构起始区块若无法证实，必须保留推断标记。

## 4. 候选与最终结论的分级

1. `observed`：真实观察到群系或疑似结构。
2. `model_compatible`：与指定生成算法的部分条件一致。
3. `candidate_seed`：输出一个或多个候选，尚未完成独立复核。
4. `independently_verified`：留出样本支持指定范围内的 Seed 结论。
5. `insufficient_evidence` / `incompatible` / `unknown`：如实给出失败与未知状态。

**任何级别均不能自动推导“完整自定义地图可复原”。**

## 5. 验收测试

- 正例：已知 Seed 的原版世界；数据采集、模型计算和验证可重复。
- 反例：错误 Seed；应拒绝或报告不一致。
- 历史混合：两个版本或不同生成机制的区块；不得静默混合求解。
- 自定义群系：注册存在但从未观察到生成；不得当作真实采样。
- 结构歧义：服务器手动建造与多候选起始区块；不得强行确认。
- 隐私：导出数据前确认脱敏，数据文件与服务器标识隔离。

## 6. 原创与可复核

优先通过官方映射下的 Minecraft 版本实现、可公开查证的技术事实与自行构造的测试世界理解规则。算法代码和实验用例自行实现，不移植第三方种子破解项目源码。

所有研究结论应附最小复现材料：游戏版本、生成规则假设、输入证据、候选输出、留出验证结果。未经确认的服务器数据不可作为公开演示资源。
