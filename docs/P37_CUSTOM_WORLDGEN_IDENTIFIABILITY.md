# P3.7 · 自定义生成器与完整64位 Seed 可辨识性研究

> 状态：**P3.7.0 只读离线审计与12项正反例已在 [GitHub Actions #38556712832](https://github.com/fxjcangku/WorldSeedLab/actions/runs/38556712832) 全部通过**；未知目标服的完整CLI回放和真正生成器逆映射仍待后续独立验证。这不是未知服务器完整64位 Seed 破解器。

## 研究目标与关键边界

WorldSeedLab 研究普通 Fabric 客户端已经接收的世界证据能否约束未知自定义地形服务器的生成规律。P3.6 自动采集结构材料/轮廓（结构 low48 条件来源）与 P1/P2/STRATA（真实群系、地表、地下剖面）始终相互独立。**未识别后台生成器映射、未知 Salt 和建筑自然来源时，不运行伪装成可靠结果的高16位筛选**。

P3.7.0 的新入口是只读 Python 3.12 标准库离线分析器。它可以读取本机单个世界/维度的 `observations.zip` 或原始目录，逐行流式分析上百万条 P1 quart 群系 + P2 16列 WORLD_SURFACE 高度 + 可选 P2.2 STRATA，严格检查世界 HMAC、维度、游戏版本、原始来源和样本格式。不会联系服务器、获取 Seed、主动请求区块、启动 Minecraft 或 Z3。

## 本机使用

前提：Python 3.12（不用安装外部 Python 包；游戏仍为Java25/Fabric）。

```powershell
python scripts/research_p37_custom_worldgen.py --input "D:\取证\observations.zip" --json-out "D:\取证\p37-anonymous-summary.json"
```

也可以将 `--input` 指向 `.minecraft/config/worldseedlab/observations/worlds/<HMAC>/dimensions/<维度hash>` 的单一原始目录。只读旧文件，新报告仅在明确传入 `--json-out` 时写到用户指定位置。报告**不含精确世界坐标、HMAC、服务器名称、服务端地址、Seed 及本机 identity.key**。不用生成服务端存档或额外取证；为了保留空间规律，仍需在私有设备上持有原始数据，公开只分享汇总。

可选的 `--salt-hypotheses 14357617,14357844` 只登记两个未知 Salt 假设数量，**不会自动验真、运行 Z3 或断言原版RandomSpread规则适用**。

## 当前已实现的严谨分析

- **P1 真正客户端群系**：仅接受 `kind=BIOME_OBSERVATION` 和 `origin=CLIENT_OBSERVATION`、quart中心坐标，不把服务端合成/手工标签冒充观测。统计群系 ID、命名空间和已观测区域，不分享原始坐标。发现 `terralith:` 等非 `minecraft:` 注册ID，说明“未经修改的原版群系注册表模型不能原样解释这些观察”，**不等于发现真实服务端是某个具体生成器**。
- **P2 真实地形**：只接受 `schema=2`、16列 `WORLD_SURFACE` 高度图，统计地表高度范围、区块起伏、原始重复行。不同历史会话的同一块高度不同，只列“疑似混合或玩家改动”，不能仅凭高度变化证明世界更换Seed。
- **P2.2 地层**：独立统计 `schema=4` SURFACE/STRATA。地下剖面若未主动设置 STRATA，报告必须显示缺失，不能通过高度图推断地下地层。
- **独立区域与留出能力**：统计P1/P2双链均覆盖的32×32区块宏区域，并额外采用 **保守至少1024方块间隔** 的空间筛选。对结构假设显示未来2FIT+1HOLDOUT的地区数量资格；对真实原版群系模型的高16候选研究，需**至少3FIT+2HOLDOUT共5处**空间独立样本。输出的都只是未来可以划分的候选区，**没有自动对任何Seed或生成器运行模型拟合/留出验证**。地区数量不是世界覆盖率百分比。
- **模型判定**：生成器=UNKNOWN，结构自然来源=UNKNOWN，Salt=UNKNOWN；没有自然起点真值不导出low48，没有经过验证的自定义世界生成映射及独立HOLDOUT就绝不宣称完整64位可辨识。原版生物群系假设冲突与完整世界Seed存在与否不可混淆。
- **失败保护与资源限制**：逐行流式读，单文件≤2GiB、单行≤64KiB字符、行数≤800万、最多4096群系ID、16384个宏区域、50万个区块去重键；多个世界/维度或版本混合、来源伪造、坐标/格式缺失、安全容量超限时直接拒绝。ZIP只读取固定白名单文件，不解压未知文件。`--json-out` 必须是一个**不存在的新JSON文件**，绝不覆盖输入ZIP、原始日志或现有报告。

## 与现有求解器接口

P3.4 `P34WorldgenCompatibilityAudit` 已提供结构/群系双轴兼容性判定，但它要求研究者显式提供可验证模型、独立来源和 FIT/HOLDOUT；不接受P2.6材料簇冒充真实起点。本次 P3.7.0 首先核对**真实观察数据是否有资格进入未来生成器模型研究**，尚未提供某个未知 Terralith、插件或混合噪声生成器的逆函数。只有真实受控世界证明映射、Salt和生成历史，再增量接入可验证模型。

## 仍待研究与不能承诺的结论

1. P3.7.1：面向独立受控自定义生成器构建带参数、版本与来源验证的可插拔前向预测模型，先检测模型冲突，绝不从群系ID或高程直猜Seed。
2. P3.7.2：真实旧区块/预生成混合历史、未知 Salt 多假设的受控正反样本，逐候选执行不同区域2FIT+1HOLDOUT和跨独立证据源验证。
3. P3.7.3：只有生成器映射在目标服务器上成立、高16全域验证可复算、模型下候选集合唯一且有独立HOLDOUT，才可讨论该**条件模型下**完整64位 Seed 可辨识；否则始终 UNKNOWN / INSUFFICIENT_EVIDENCE / MODEL_CONFLICT / GENERATOR_UNKNOWN。

更多输入来自你后续正常跑图的本地文件，不需要上传私人服务器明文坐标；公开报告必须脱敏。两版真正 Minecraft GUI 自动结构验证仍属于 P3.6.2 独立 CI，不能由 P3.7 Python 合成样本代替。
